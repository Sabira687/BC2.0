# Механика продукта: картриджи и карта памяти

> Пользователь учится пользоваться ИИ-ассистентом **внутри самого ассистента**. Мы выдаём ему цифровые предметы — блоки инструкций в ностальгическом «игровом» стиле. Вставленный в чат предмет переключает ИИ в режим наставника по самому себе.
> Механика вставки проверена массовым кейсом: Snickers Hungr.AI (август 2026) — блок инструкций, оформленный как шоколадка, который копируют с сайта и вставляют в ChatGPT.
> **Демо:** один ассистент — **Claude Code**.

---

## 1. Предметы

Единый стиль — **игровая консоль начала 2000-х**: картриджи запускают игру, карта памяти её сохраняет.

| Предмет | Когда вставлять | Что делает |
|---|---|---|
| **Картридж LEARN** (обучение) | В **чистую** сессию | Включает режим обучения: теория → практика прямо в терминале → мини-проверка. Учит только функциям самого ассистента |
| **Картридж CO-OP** (помощь) | В **середину** сессии, где уже идёт работа над задачей | Продолжает помогать с задачей и параллельно показывает «Pro move»: как сделать это лучше средствами ассистента и почему |
| **Карта памяти** (сохранение) | В конце **любой** из двух сессий | Подводит итог, выдаёт **код сохранения** и ссылку, выключает режим |

Шаблоны предметов: [`items/learn-cartridge.md`](../items/learn-cartridge.md), [`items/help-cartridge.md`](../items/help-cartridge.md), [`items/memory-card.md`](../items/memory-card.md). Переменные `{{...}}` заполняются по анкете пользователя.

### Правила сессии
- **Сессия не заканчивается сама** — ни по времени, ни по завершению темы. После модуля ИИ коротко празднует и предлагает: следующий модуль, ещё практику или другой модуль.
- **Закрывает сессию только карта памяти.** Одна и та же карта закрывает и LEARN, и CO-OP: она сама находит в диалоге активный картридж.
- **Учим только самому ассистенту.** Картридж Claude Code не учит ChatGPT и наоборот.
- **В CO-OP задача пользователя важнее.** Не больше одного Pro move за ответ и только когда он действительно полезен. В анкете объяснения можно выключить: тогда ИИ просто использует лучший приём, без пояснений.

## 2. Как инструкции «записываются» в память сессии

1. **Вставленный текст остаётся в контексте** всего диалога: ИИ видит его в каждом следующем ответе.
2. **Явное правило в предмете:** «действует до карты памяти; не сбрасывать из-за времени, смены темы или завершения задачи».
3. **Строка статуса в конце каждого ответа**, например `▮ LEARN · P7K3Q · m2 Plan mode · checks 1/2`. Она работает как игровой HUD: пользователь видит, что режим активен, а сам ИИ каждый раз заново «проговаривает» его — это удерживает режим в длинном диалоге.
4. **Скрытый журнал:** ИИ ведёт учёт пройденных модулей, отработанных приёмов и проверок — из него потом собирается код сохранения.
5. **Если диалог очень длинный** и контекст сжимается, картридж можно вставить повторно: тот же ID игрока — продолжение с того же места.

## 3. Код сохранения

### Формат
```
SV1-<игрок>-<режим>-C<пройдено>-P<текущий>-T<приёмы>-Q<успех>o<всего>
```
Пример: `SV1-P7K3Q-L-C12-P3-T125-Q3o4`

| Часть | Значение | Пример |
|---|---|---|
| `SV1` | Версия формата | |
| `P7K3Q` | ID игрока (зашит в картридж при генерации) | |
| `L` / `H` | LEARN или CO-OP | `L` |
| `C…` | Пройденные модули | `C12` — m1 и m2 |
| `P…` | Модуль в процессе | `P3` |
| `T…` | Коды отработанных приёмов | `T125` — @-файлы, plan mode, /clear |
| `Q…o…` | Проверки: пройдено из всего (в CO-OP — применено Pro move из показанных) | `Q3o4` |

### Почему это надёжно
- **ИИ ничего не вычисляет** — он только копирует готовые токены: ID из картриджа, номера модулей и коды приёмов из списков в картридже. С такой задачей модели справляются стабильно, в отличие от подсчёта контрольных сумм или кодирования.
- **Сайт разбирает код по шаблону** и терпим к мелким ошибкам (регистр, лишние пробелы).
- **Логин не нужен:** ID игрока создаётся при заполнении анкеты и связывает код с профилем на нашей стороне.
- **Личных данных в коде нет** — только ID и прогресс.

### Как прогресс попадает в приложение
1. Карта памяти выдаёт код и ссылку `<сайт>/save/<код>`.
2. В Claude Code ИИ предлагает сам открыть ссылку командой `open` — пользователь подтверждает, и браузер открывается.
3. Сайт разбирает код, обновляет прогресс и показывает экран сохранения.
4. Запасной путь: вставить код вручную в поле на сайте.

## 4. «Магия»: ключевые моменты впечатления

| # | Момент | Что видит пользователь |
|---|---|---|
| 1 | **Вставка картриджа** | ИИ отвечает ретро-экраном загрузки, обращается по имени, показывает карту квестов ✓ / ▸ / · |
| 2 | **HUD** | В каждом ответе — строка статуса: режим, модуль, проверки |
| 3 | **CO-OP «видит» прошлое** | Сразу после вставки ИИ разбирает уже сделанную работу: «вот что помогло бы тебе 10 минут назад» |
| 4 | **Практика по-настоящему** | Задания выполняются в реальном терминале (папка `./dojo`), а не в учебной песочнице |
| 5 | **Сохранение** | Экран `SAVING... 100% · GAME SAVED ✓`, код и итог сессии в двух строках |
| 6 | **Браузер открывается сам** | ИИ открывает ссылку → на сайте анимация «чтения карты памяти» → разблокируются модули и приёмы |
| 7 | **Следующий картридж** | На сайте уже готов картридж «Continue» с нужного модуля |

## 6. Сценарий демо

- **Ассистент:** только Claude Code.
- **Анкета:** один путь. Остальные варианты ответов видны, но недоступны — понятно, что они существуют, но в демо выбирается один.
- **Видео (вторая часть питча):** один пользователь, один ассистент, обе сессии:
  1. Анкета → генерация → картридж LEARN → обучение → карта памяти → прогресс на сайте.
  2. Рабочая задача → картридж CO-OP в середине → Pro moves → карта памяти → прогресс на сайте.

## 7. Масштабирование

- **MCP-коннектор:** тот же механизм, но автоматический — ИИ сам записывает прогресс и загружает следующий модуль, без копирования кода. Суть продукта не меняется, становится удобнее.
- **Другие ассистенты:** ChatGPT, Claude, Gemini, Cursor — отдельные наборы картриджей.
- **Коллекция картриджей:** ИИ-ассистенты обновляются каждый месяц → новая функция = новый картридж.
